|------|-----------|------------|-----------|------------|-------------|

## 关键发现

### 1. RL 模型在验证集上的表现

✅ **Phase 2 (LayerPolicy)**:
- 验证集 IoU: 0.8085
- vs Baseline最佳 (0.8180): -1.2%
- vs Baseline最终 (0.8125): -0.5%
- **结论**: 与 Baseline 基本持平，略低

✅ **Phase 3 (Joint)**:
- 验证集 IoU: 0.8111
- vs Baseline最佳 (0.8180): -0.8%
- vs Baseline最终 (0.8125): -0.2%
- **结论**: 与 Baseline 基本持平，略优于 Phase 2

### 2. 训练集 vs 验证集 vs 测试集

| 模型 | 训练集 IoU | 验证集 IoU | 测试集 IoU | 训练→验证差距 | 验证→测试差距 |
|------|-----------|-----------|-----------|-------------|-------------|
| **Phase 2** | 0.9184 (平均) | 0.8085 | 0.7684 | **-12.0%** | -5.0% |

⚠️ **严重过拟合**: 
- RL 训练过程中的 IoU (0.91-0.92) 远高于验证集 (0.81)
- 说明 RL 训练过度优化了训练集样本

### 3. 验证集→测试集的泛化能力

所有模型在验证集→测试集都有约 **5%** 的性能下降：
- Baseline: -5.9%
- Phase 2: -5.0%
- Phase 3: -5.4%

✅ **结论**: 这是正常的泛化差距，所有模型表现一致

### 4. RL 方法的实际效果

基于验证集和测试集的对比：

| 对比维度 | Phase 2 vs Baseline | Phase 3 vs Baseline |
|---------|-------------------|-------------------|
| 验证集 IoU | -1.2% ❌ | -0.8% ❌ |
| 测试集 IoU | -0.1% ❌ | -0.3% ❌ |
| 验证集 DICE | -1.2% ❌ | -1.0% ❌ |
| 测试集 DICE | -0.1% ❌ | -0.2% ❌ |

**结论**: 
- ❌ RL 方法**没有提升性能**
- ❌ 反而略微下降 (0.1-1.2%)
- ⚠️ 训练集的高 IoU (0.91+) 是**过拟合的表现**

## 问题分析

### 1. 为什么训练集 IoU 这么高？

**原因**:
1. RL 训练反复在相同的训练样本上优化
2. 训练 5000 步，每步采样 4 个样本，总共优化了 20,000 次
3. 训练集可能只有几百个样本，被重复优化了数十次
4. RoutingPolicy 和 LayerPolicy "记住"了训练样本的特征

### 2. 为什么验证集/测试集没有提升？

**原因**:
1. **过度专门化**: 策略针对训练集样本优化，不泛化
2. **Baseline已经很好**: Noisy-TopK的随机性提供了正则化
3. **RL奖励设计问题**: 可能需要更好的奖励函数
4. **缺少正则化**: 没有在验证集上监控和early stopping

### 3. 为什么 Phase 3 比 Phase 2 略好？

在验证集上:
- Phase 3 IoU: 0.8111
- Phase 2 IoU: 0.8085
- 差距: +0.0026 (+0.3%)

**可能原因**:
- Phase 3 联合训练 3000 步，比 Phase 2 的 5000 步少
- 更少的训练步数 = 更少的过拟合
- 这支持了"训练步数过多"的假设

## 建议

### 立即可做

1. **使用早期 checkpoint**:
   - Phase 2: 尝试 step 1000-2000 的 checkpoint
   - Phase 3: 尝试 step 500-1000 的 checkpoint
   - 可能会有更好的泛化性能

2. **对比不同训练步数**:
   ```bash
   # 评估 Phase 2 的早期 checkpoint
   python eval_hierarchical_policy.py \
     --hier_ckpt rl_hier_layer_only-251119/checkpoints/step_1000.pt \
     --split val
   ```

### 需要重新训练

1. **添加验证集监控**:
   - 每 100 步在验证集上评估
   - 使用 early stopping
   - 保存验证集上最佳的模型

2. **减少训练步数**:
   - Phase 2: 1000-2000 步
   - Phase 3: 500-1000 步

3. **增强正则化**:
   - 增大 KL 系数 (0.05 → 0.1)
   - 增大熵正则化 (0.01 → 0.05)
   - 数据增强

4. **使用更大的训练集**:
   - 或者减少采样频率
   - 避免重复优化相同样本
