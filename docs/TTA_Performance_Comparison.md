## 逐步优化历程

### 版本 1: 初始实现（有问题）

**特点**:
- 使用 OpenCV (cv2) - 依赖问题
- 通过 DataFrame 调用推理 - 列检查问题
- 使用 scipy.ndimage.rotate - CPU 100%，很慢
- 没有内存管理 - 内存泄漏
- 模型可能在 CPU - 速度慢

**性能**:
- 单图 TTA: ~60-120 秒
- 600 图: ~10-20 小时
- CPU: 100%
- 内存: 持续增长到 20GB+

---

### 版本 2: 依赖修复

**改进**:
- ✅ 移除 cv2，用 scipy/skimage 替代

**性能**:
- 无明显变化（scipy/skimage 也慢）

---

### 版本 3: API 和 GPU 修复

**改进**:
- ✅ 添加 MultiModalPredictor API
- ✅ 确保模型在 GPU 上
- ✅ 直接模型前向传播

**性能**:
- 单图 TTA: ~60 秒 → ~5-10 秒
- GPU: 0% → 70-100%
- 但 CPU 仍然 100%，内存仍然泄漏

---

### 版本 4: 内存和 CPU 优化（**当前版本**）

**改进**:
- ✅ **用 PIL 替代 scipy.ndimage.rotate**（关键优化）
- ✅ **用 PIL 替代 skimage.transform.resize**
- ✅ **显式内存管理**（del + gc.collect()）
- ✅ **定期清理 GPU 缓存**
- ✅ **显式关闭 PIL 对象**

**性能**:
- ✅ 单图 TTA: ~1-2 秒（**30-60x 提升**）
- ✅ 600 图: ~10-20 分钟（**30-60x 提升**）
- ✅ CPU: 40-60%（**-40%**）
- ✅ 内存: 3-5GB 稳定（**-75%，修复泄漏**）
- ✅ GPU: 70-100%

## 优化技巧总结

### 1. 选择合适的库

- ✅ **PIL**: 图像处理首选（快、内存效率高）
- ⚠️ **scipy**: 仅用于科学计算，不适合大规模图像操作
- ⚠️ **skimage**: 高质量但慢，仅在必要时使用

### 2. 显式内存管理

```python
# ✅ 好习惯
for i in range(1000):
    data = process(i)
    use(data)
    del data  # 显式删除
    
    if i % 10 == 0:
        gc.collect()  # 定期回收
```

### 3. 关闭资源

```python
# ✅ 好习惯
img_pil = Image.open('image.jpg')
# 使用 img_pil...
img_pil.close()  # 释放文件句柄和内存
```

### 4. 清理 GPU 内存

```python
# ✅ 好习惯
with torch.no_grad():
    output = model(input)
    result = output.cpu().numpy()
    del input, output  # 释放 GPU tensor

if idx % 10 == 0:
    torch.cuda.empty_cache()  # 清理缓存
```

## 故障排查

### 如果内存仍然增长

1. **检查是否最新代码**:
   ```bash
   git pull
   git status
   ```

2. **重新启动 Python 进程**:
   - 旧进程可能还持有内存

3. **检查垃圾回收**:
   ```python
   import gc
   gc.set_debug(gc.DEBUG_STATS)
   ```

### 如果 CPU 仍然很高

1. **检查 PIL 版本**:
   ```bash
   pip show Pillow
   # 建议 >= 9.0
   ```

2. **检查是否在使用旧的 scipy**:
   ```bash
   python3 -c "import sys; import tta_utils; print('Using scipy' if 'scipy' in str(tta_utils.RotateTransform) else 'Using PIL')"
   ```
